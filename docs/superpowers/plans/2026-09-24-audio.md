# Group audio implementation

Approved scope: group-local listening sessions and four-person voice rooms. No forced audio, no private-chat audio, no paid upgrades.

## Provider feasibility

YouTube's official iframe API supports visible video/playlist embeds, play/pause/seek and player state events. Use an explicit Join listening action before loading an embed; keep its branding and controls intact. Server session state can coordinate commands, but buffering, advertisements, unavailable videos and browser autoplay restrictions prevent a sample-accurate guarantee. Spotify music embeds remain provider-controlled individual playback; do not present them as synchronized Web Playback SDK sessions. Unsupported URLs open externally only after user choice.

Sources checked 2026-09-24:
- https://developers.google.com/youtube/iframe_api_reference
- https://developer.spotify.com/documentation/embeds/tutorials/creating-an-embed
- https://developer.spotify.com/documentation/web-playback-sdk
- https://developers.cloudflare.com/realtime/turn/generate-credentials/
- https://developers.cloudflare.com/realtime/sfu/platform/pricing/

Cloudflare TURN is a candidate for relay connectivity; credentials must be server-generated and short-lived. Published allowance is 1,000 GB/month shared by SFU/TURN with overage charges. Do not enable billing without authorization. A STUN-only pilot is not proof of connectivity on restrictive networks.

## Music implementation tasks

1. SQL state: membership-protected session, queue, listener leases and skip votes. Group lock serializes writes. Host succession selects earliest continuously connected listener after 45-second lease expiry. Last listener leaving ends the session. Queue max100. Only host controls play/pause/seek and ordering. More-than-half votes skip the current item. Validate provider IDs on the server; never fetch caller-provided URLs.
2. React player: link parsing/preview, queue, explicit join/leave, host transfer, synchronized YouTube commands and honest Spotify mode. Reconcile server revisions, indicate player errors and autoplay blocks. User pause/mute remains local for non-hosts.
3. Song matches: server-side provider search, real result selection before enqueue, no model-invented links. Provider search credentials are a separate external dependency.
4. Tests: SQL outsider and removed-member rejection, host succession, stale revisions, skip threshold, queue constraints; browser flows with player fake; actual allowed-embed checks.

## Voice implementation tasks

1. Membership-authorized signaling, session IDs, 4-person atomic cap, short leases and automatic cleanup. Store only short-lived SDP/ICE signaling, never audio.
2. WebRTC peers, muted start, explicit microphone permission, open mic and hold-to-talk, release on blur/cancel/disconnect, teardown tracks on leave/removal/group switch. Show connection/audio-permission errors.
3. Optional TURN credential Edge Function with strict membership/rate checks and operator-set secrets. No long-term TURN credential in Vite.
4. Verify two browser contexts with synthetic audio, room cap and member removal; real mobile/network relay verification before calling voice production-ready.
