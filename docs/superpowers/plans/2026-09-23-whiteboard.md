# Collaborative whiteboard implementation plan

Goal: a persistent group board, maximum20 tabs, simultaneous editing on a fixed1920x1080 canvas with25–400% zoom.
Spec: ../specs/2026-09-21-apu-chatter-design.md
Architecture: authoritative operations with stable UUID shape IDs and per-shape revision checks. Independent edits commute; conflicting edits fail/reload instead of overwriting. Postgres stores shapes, tombstones and operation ownership; Realtime signals refetch. Ephemeral cursors use authorized presence channels only after membership checks. Text edits acquire short leases; cursor movement never writes durable SQL.
Files: CLI-generated board migration, src/features/board/{BoardPanel,boardModel}.tsx, scripts/check-board.mjs and browser two-client check.
RPCs: create_board_tab(group,name), rename_board_tab(tab,name), write_board_shape(tab,id,expected_revision,data,deleted). Server validates bounded coordinates, max2000 points/stroke, allowed pen/highlight/text kinds, size/color, membership and rate limits. Group lock enforces20 tabs under concurrent adds. Shape writes lock group then tab, use stable shape ID and expected revision; return revision. Personal undo stores only actor's operations in browser memory and submits inverse with expected revision; conflict preserves newer edits and explains inability to undo. Eraser deletes whole object. No arbitrary SVG/HTML accepted.
Tests: outsider reads/writes denied;21st tab rejected; independent shape writes both persist; stale revision cannot overwrite; erase/undo affects only targeted operation; invalid coordinates/payloads rejected; removed member cannot write; reconnect uses canonical shapes. UI tests: pen/highlighter/text/eraser, zoom/pan fixed bounds, tab rename, personal undo/redo and reduced-motion/mobile controls.
Execution: implement failing SQL tests then schema/RPCs, editor then browser tests, inspect desktop/mobile once, apply migrations and verify real two-client updates. Do not claim CRDT convergence beyond the explicit operation/revision model.
