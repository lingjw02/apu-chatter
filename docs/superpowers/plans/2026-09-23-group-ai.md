# OpenRouter AI implementation plan

Goal: explicit group summaries/decisions/notes, plus one automatic weekly summary. No private-chat context or continuous model calls.
Spec: ../specs/2026-09-21-apu-chatter-design.md
Files: CLI AI migration; supabase/functions/{group-ai,weekly-ai}/index.ts with shared provider helper; src/features/ai/AIPanel.tsx; SQL limit/ownership tests and mocked-provider tests.
Interfaces: set_group_ai(group,enabled) owner only; request_ai_job(group,kind,client_id) verified member, enabled group,3/user/day and20 deployment requested/day; weekly jobs separate unique(group,week) with bounded2 attempts; ai_jobs stores state/result/source IDs and coverage, no copied input corpus. Completion is service-only and rechecks group-enabled state. All reads require current group membership.
Provider: fixed free allowlist, OPENROUTER_API_KEY only in Edge secrets, model openrouter/free initially, no paid fallback/plugins/tools. POST chat/completions max_tokens1000,35second timeout. Input newest200 eligible group messages in selected range and <=6000UTF8 bytes plus fixed prompt (<8000 token worst-case budget); label partial coverage. Strip common credential/email patterns, treat text as untrusted quoted data; no tool access and no automatic actions. Include only source IDs already selected and build in-app source links ourselves. Results are plain text.
Weekly scheduler: every15min invokes a secret-authenticated worker, claims at most5 due enabled groups after Monday09:00 local time. Previous local week only; skip no-content weeks; unique key prevents duplicate successful posts. Failed jobs retry once after1h; no work while key unconfigured. Owner opt-in disclosure explains external group-text processing and automatic weekly output; members explicitly request all other runs. Quota/provider failure never blocks normal chat.
Tests: outsider/disabled denial, quotas, job retry idempotence, member reads, owner enablement, weekly due timezone/unique keys, failed-provider state and source-group isolation. Live model test only after a valid replacement key is added locally.
